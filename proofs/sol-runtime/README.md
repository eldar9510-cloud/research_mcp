## Narrow module/interface

- `runInvestigation({question,scope,signal?}, {modelRuntime,adapter,limits?})` in `src/research.mjs` accepts either injected dependencies or `createDependencies({signal})` (the live entrypoint uses this so runtime initialization shares its deadline). It returns `completed | incomplete | failed | cancelled`, a safe reason code, configured model/effort and bounds, attempted model/tool counts, tool-output bytes, available per-response usage, inspected source URLs/full bounded passages/visible-text digests, and (only if completed) a cited short answer. Invalid input/limits throw. Optional bound overrides **only decrease** starting limits.
- `adapter`: precisely two methods, `search(query,{signal,limits})` and `fetch(url,{signal,limits,offset?,contains?})`; the active concrete integration is `createBraveRfcAdapter({token,fetchImpl?})` in `src/brave-rfc.mjs`. It performs one GET to **only `https://api.search.brave.com/res/v1/web/search`**, with `q=site:rfc-editor.org <bounded query>` and `count=3` (or a smaller requested limit). Only this search request gets `X-Subscription-Token`; direct RFC requests receive only their source Accept header. No answer API, search HTML parser, provider framework, router or fallback exists. Every candidate destination passes the unchanged `sourceUrl` allowlist: HTTPS `rfc-editor.org` or `www.rfc-editor.org`, `/rfc/rfc2606.html|txt` only, no credentials, port, fragments or queries. At most three returned leads have titles ≤120 and snippets ≤180 characters; leads are not cited evidence.
- Search requires HTTP 200, no redirect, `application/json` and a complete body strictly below the raw byte cap **before JSON parsing**. Malformed JSON/schema fails with a fixed safe code; an explicit `web.results:[]` or entirely filtered results yields `[]`. Refused status/type bodies and over-limit bodies are cancelled. Transport/read/abort exceptions and API error bodies are never echoed. Requests use `redirect:'manual'` and `credentials:'omit'`; no cookie jar, bootstrap, pagination, automatic retry or endpoint fallback. Direct RFC request, extraction, passage selection and truncation logic are copied unchanged from the reviewed baseline's source half.
- `src/duckduckgo-rfc.mjs` and its tests remain **inactive historical offline regressions**, not a configurable/live fallback. The original rejected DDG layout's root cause is still unknown; replacing the backend is not a demonstrated fix for it.
- `makeLiveDependencies({signal,braveSearchApiKey})` in `src/live-dependencies.mjs` validates the host-supplied key **before** creating Pi's supported `ModelRuntime` (without network catalogue refresh). Missing/blank keys fail before runtime/auth initialization or model dispatch. Only the gated `live-once.mjs` reads `BRAVE_SEARCH_API_KEY` from the host environment; the adapter/factory never discover credentials in files or global configuration. Call it **only under the parent's approved live-proof gate**. The harness does not directly read, print or serialize Pi credential contents; the SDK resolves authentication internally. The isolated loader supplies only a small instruction, no globally discovered extensions, skills, context files, shell, read/write/edit, Git, acceptance, MCP dispatch or nested researcher. Session and settings are in memory; there is no persistent transcript or hidden reasoning artifact. These tool restrictions are **not** an OS sandbox.

## Starting per-run bounds (not a price cap)

| Bound | Starting value |
|---|---:|
| Wall clock | 180,000 ms (3 minutes) |
| Model requests | at most 5 dispatched by this process (an extra attempted request is rejected before dispatch) |
| Research tool attempts | 4 (invalid/rejected calls count) |
| Each tool deadline | 12,000 ms |
| Total model-visible research-tool output | 10,000 UTF-8 bytes |
| Per-model-response streamed visible output | 1,500 JavaScript characters including text, visible thinking and tool-call argument JSON; overflow aborts the run (final answer shares this bound) |
| Search results | at most 3 official RFC 2606 URLs |
| Brave JSON raw search response | 65,536 bytes; reaching the cap fails closed, even if an exactly-cap-sized document might be complete (no partial hits) |
| Each fetched RFC raw response | 65,536 bytes (truncation disclosed; material beyond this cap cannot be inspected by this proof) |
| Each selected fetched passage/model-visible text | 2,400 characters, by offset or case-insensitive `contains` within extracted text (location/continuation and truncation disclosed; full selected passage retained for review) |
| Question/scope/search query/URL/`contains` selector | 300/400/180/512/80 characters (`offset` at most 65,536) |

Response byte caps bound retained bytes from `fetch`'s response body (normally decompressed by Node), not compressed wire traffic or a fetch implementation's single incoming chunk allocation. The active search path parses only bounded JSON, not search HTML. Historical DDG lexer regressions remain offline; separate SDK-tool tests preserve real tool/wall timer outcomes. These are regression checks, not hard latency guarantees: timers cannot preempt synchronous JavaScript.

The overall wall timer starts **before live dependency initialization, auth and SDK session creation**. Those awaits are raced against the wall deadline and user abort, with a session that finishes creating late disposed. A non-cooperative setup/auth/provider/tool may continue underlying work after local return. Every tool receives the SDK abort signal and an independent timeout; tool attempts are counted at SDK `tool_execution_start`, including schema-rejected and unknown calls, and extra attempts do not execute adapters. In-flight provider requests/tools may not stop instantly, and incurred usage cannot be refunded. No instant cancellation, process sandbox, **remote token/cost ceiling**, or durable partial-job recovery is claimed. The installed Codex SSE serializer **does not send** `model.maxTokens` as `max_output_tokens`: changing the catalogue property or a local option would not enforce a remote 4,096-token cap. The real controls here are wall time, model-request count, streamed **visible** output (including tool args), and bounded tool work; hidden reasoning/output and remote computation are not independently capped by a provider request field. Limit hits return `incomplete`; tool/provider faults return `failed`; user abort takes priority over an overlapping wall/internal stop. No unbudgeted model call polishes a stopped result. Visible usage is recorded only where the provider reports it, never invented costs. Full #7/#8 job artifacts/lifecycle remain out of scope.

Completion in this **RFC 2606 example-domain proof** requires a successful nonempty search, then a fetch of a returned in-scope URL, an inspected cited passage containing all three example-domain names **and** a use term, and an answer naming the same names/use. Missing or insufficient evidence is `incomplete`; a premature fetch is rejected. This is a mechanical scope check, **not** factual verification or proof that every claim is supported. Parent review must examine the full bounded `sources[].excerpt` passage (up to 2,400 characters per call), its offset/truncation and digest, plus the answer before accepting live evidence. A missing term outside the accessible raw 65,536 bytes cannot be assumed absent from the entire RFC. Excerpts and SHA-256 digests describe only the **selected visible** source passage, not the complete page. HTML extraction is intentionally simple; pages with interactive/JS-only content cannot count as inspected. No third-party page is published by this harness.

## Private first-tool-failure diagnostic (offline-verified, not a root-cause fix)

The existing outcome optionally includes one frozen `firstToolFailure: {tool, stage, code}` copy. Runs with no observed tool failure retain their previous shape. It records the **first observed failure**, even if an SDK rejection is followed by successful work; it does not change status/reason, counts, dispatch, retry, deadlines, bounds or completion guards.

- `tool`: only `research_search | research_fetch | other`. One active enum-only attempt is sufficient for the pinned SDK: owned tools force sequential execution, and unknown-tool rejections end during SDK preflight. No arguments, arbitrary tool names or call IDs are retained by the diagnostic.
- `stage`: `sdk_start | input_validation | adapter | output_validation | output_encoding | completed | unknown`. These mark existing operation boundaries, not inferred causes. `adapter` covers everything inside the adapter, including response parsing; it does not prove a network fault. `unknown` is the fallback when a boundary cannot be established.
- `code`: exact matches of a native Error's own string-valued `message` data property only for `invalid_query`, `source_out_of_scope`, `source_not_searched`, `invalid_passage_selection`, `source_passage_not_found`, `empty_source`, `tool_invalid_output`, `remote_fetch_failed`, `search_response_invalid`, `search_layout_unrecognized`, `search_challenge`, `search_response_over_limit`, `unsupported_search_type`, `unsupported_source_type`, `tool_output_limit`; otherwise `other`. An error lifecycle event before execute records only `sdk_start/sdk_rejected`, without inspecting the SDK's argument-containing validation text or result. Timeout/abort statuses remain distinct; a caught timeout has code `other`, not a guessed adapter error. An abort may return before a tool failure is observed, so the field is not guaranteed on every stopped run.

Classification rejects proxies (including revoked proxies) and non-native Error objects before reflection. Message accessors, inherited messages and non-string data values yield `other`; no message getter or proxy trap is invoked. Native Error checks do not traverse even a proxy prototype, and only an own data descriptor is read. This assumes trusted local Node built-ins, not a security boundary against hostile code in the same process.

The record is copied before tool-failure/output-limit halts and copied/frozen again in the terminal outcome; late uncooperative adapters cannot mutate it. There is no event log, provider hook, telemetry, new persistence or model-visible diagnostic. No raw message, stack, cause, header, URL, query/hash, prompt, argument, body, provider payload, hidden reasoning or arbitrary name is added. Existing bounded inspected-source evidence remains unchanged.

Offline tests cover input/scope/order failures, synthetic malformed/challenge/request responses, unknown exceptions, output normalization/byte limits, real SDK rejection, exact-whitelist sanitization and late resolution. These controls distinguish previously ambiguous paths; **the actual rejected DDG response was not captured, and its root cause remains UNKNOWN**. This adaptation changes the selected backend, not diagnostic classification, source extraction or runtime semantics.
